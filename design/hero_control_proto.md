## Глоссарий

| Термин | Значение |
|---|---|
| **Из позиций** | Подход: движение задаётся точками и расстояниями, без физики и анимации. Противоположность — «симуляция». |
| **Блок** | Отдельный рабочий кусок механики с одной задачей, проверяемый сам по себе. Из сочетания блоков складывается (эмерджентно) поведение. |
| **Зафиксировано** | Автор принял решение — больше не менять без его слова. |
| **Тело, B** | Центр героя (таз) на полу. Тело — круг r = 0.2 м. |
| **Плечо, S** | Точка, откуда растёт рука. **Сбоку от тела: 0.2 м вправо от лица** (`shoulderSide`), как у модели героя — рука правая. Крутится вместе с телом. |
| **Кисть, H** | Точка на полу, куда поставлена рука (клик ЛКМ). |
| **Локоть, E** | Сгиб между плечом и кистью; рисуется из длин a и b. |
| **a, b** | Плечо руки (0.32 м) и предплечье (0.30 м). |
| **Длина руки, L** | L = a + b = 0.62 м — досягаемость. |
| **Сгиб до упора, dMin** | Ближе этого (0.18 м) тело к кисти не подтягивается. |
| **Линия хода (траектория)** | Прямая через плечо и кисть в плоскости XZ: по ней ездит плечо, тело — рядом, сбоку. На схемах — зелёная, со стрелками в обе стороны. |
| **C** | Длина хода по линии: от «рука вытянута» до «согнута до упора», C = L − dMin. |
| **Хват** | Состояние, пока ЛКМ зажата и кисть стоит на полу. |
| **Жест** | Движение мыши при хвате. Раскладывается на «езду» и «поворот». |
| **Локальная раскладка** | Жест считается в осях экрана, то есть камеры за спиной, то есть тела: Y — езда, X — поворот. Не зависит от того, где кисть. |
| **На себя / от себя** | Мышь вниз — тело к кисти; мышь вверх — от кисти. |
| **Езда** | Перемещение тела по линии хода от жеста «на себя / от себя». |
| **Поворот на месте («лопасти вертолёта»)** | Мышь вправо/влево при хвате — тело крутится вокруг центра, кисть стоит. Вправо = поворот вправо. |
| **Лицо** | Направление «вперёд» тела. На схеме — белая стрелка. Лицо там, где рука. |
| **Лицом / спиной** | Тело едет туда, куда смотрит (сила 1.0), или назад (0.45). |
| **Досягаемость** | Где может встать кисть: не дальше L и внутри сектора перед лицом. |
| **Сектор, разброс руки (слой движения)** | Угол перед лицом (−50°…+70°), куда ставится кисть и где езда в полную силу. |
| **Зона поворота (слой поворота)** | На сколько можно довернуть тело за один хват: 180° (±90° от лица). |
| **Затухание езды** | За разбросом руки езда плавно слабеет и к 100° от лица гаснет. |
| **Материал стены** | Аналог физического материала без физики: тело скользит вдоль препятствия с трением `wallFriction`. |
| **Скольжение** | Убрать из хода составляющую «в стену», оставить вдоль. В углу — по каждой стене по очереди. |
| **Перестройка линии** | После скольжения или поворота линия хода заново проводится через кисть и новое место плеча. |
| **Выталкивание** | Если тело всё же оказалось в стене, его выдавливает наружу по нормали, потом линия перестраивается. |
| **Препятствие** | Прямоугольник на полу по габаритам кубика. Тело в него не входит, кисть на него не встаёт. |
| **Уровень** | Высота поверхности под телом (`groundY`). Все высоты считаются **от своего уровня**, а не по самому верху. |
| **Порог подъёма / спуска** | Насколько выше (`maxStep` 0.4) и ниже (`maxDrop` 0.4) своего уровня тело может встать. За порогом — уступ или край, он работает как стена. |
| **Досягаемость кисти по высоте** | Кисть ложится не выше уровня + `handUp` (0.5) и не ниже уровня − `handDown` (0.5). |
| **Ввод работает всегда** | Хват есть даже вплотную к стене или краю: кисть встаёт у кромки. Отсекается исполнение — запрещённое (залезть, упасть, в стену) не происходит, разрешённое (отъехать, развернуться) проходит. |
| **Автообход (анти-вектор)** | Препятствия рядом отталкивают тело в ходе, и в углах тело уводит вбок, а не заклинивает. |
| **Тело для руки** | Круг `armKeepOut` 0.15 м от центра тела: рука (отрезок плечо → кисть) через него не проходит — в себя не залезть. |
| **Трасса, карта** | Полоса препятствий из текстовой карты, клетка 0.6 м: `#` стена, `o` столб, `S` старт, `F` финиш. |
| **Подсказки (гизмос)** | Отрисовка сектора, линии хода, стрелок жеста и лица (`showHints`). Для игры выключены. |
| **Наклон камеры** | ПКМ + мышь вверх/вниз. Поворот камеры влево-вправо — только вместе с телом. |
| **Подвижный элемент (`ProtoMover`)** | Лифт, челнок, поворотный круг, карусель. Тело на нём едет вместе с ним; кисть, держащаяся за него, — тоже. |
| **Крутой склон** | Поверхность круче `steepAngle` 35° (выход из «крутого» — при 32°). Без опоры тело на нём сползает. |
| **Опора** | Хват, который держит: кисть на пологом или на зацепе. Кисть на крутом без зацепа — не опора. |
| **Зацеп (`ProtoHold`)** | Поручень, перила, столб, ручка — отрезок, за который кисть держится на любом склоне. |
| **Автозахват** | Курсор рядом с любой частью зацепа — кисть сама берёт ближайшую точку, до которой достаёт. |
| **Кромка** | Верх уступа выше порога шага (до `climbUp` 0.8), за который можно взяться, если под ним сплошное и он в досягаемости. |
| **Подтягивание / перевал** | У кромки жест «на себя» поднимает тело; поднялся достаточно — тело само заходит наверх (перевал). |
| **Сторожа (`ProtoWatch`)** | Проверки на каждом кадре: тело в стене, рука длиннее досягаемости, рука сквозь тело, скачки. |
| **Бот (`ProtoBot`)** | Водит героя тем же вводом, что мышь: бродяга по арене или маршрут к цели. Ищет ловушки (нельзя сдвинуться никуда). |
| **Выступ (`ProtoNub`)** | Камень, край, неровность стены: короткий зацеп по верху кубика. Держит, как поручень, но прилипает только рядом; на нём можно повиснуть, перевалить нельзя. Вернулся из прежнего «автозацепа r». |
| **Предмет (`ProtoItem`)** | То, что рука берёт и тащит. Маркер на кубике в декоре: не стена, не опора. Зона 10 арены. |
| **Перехват, LOCK** | Блоки из прежних версий (рука переставляется сама; предмет на голове или у плеча). Будут возвращаться по одному. |

## Принцип

- **Не симуляция, а позиции.** Ни физики, ни анимации: только точки, расстояния и прямые. Попытка симулировать (IK + физика + десяток правил сразу) дала «натужное», неуправляемое поведение и была отвергнута.
- **Механику собираем блоками.** Отдельные рабочие куски, проверяемые по одному; поведение должно складываться из их сочетания, а не появляться из монолита.
- Игрок выбирает точку на экране и жмёт ЛКМ. С этого момента набор действий ограничен — только несколько жестов.

## Модель

| Точка | Что это |
|---|---|
| **B** | тело (таз), центр круга r = 0.2 |
| **S** | плечо: **0.2 м вправо от лица** (`shoulderSide = 0.2`; у модели `upperarm_r` ≈ 0.21 м от центра). Крутится вместе с телом |
| **H** | кисть: точка на полу, куда пришёлся клик |
| **E** | локоть, рисуется между S и H: два звена `a = 0.32`, `b = 0.30`, сгиб наружу (вправо) |

- Длина руки **L = a + b = 0.62 м**, сгиб до упора — **dMin = 0.18 м**.
- **Линия хода** — прямая через S и H, только в плоскости XZ. По ней ездит плечо: от «рука вытянута» (|S−H| = L) до «согнута до упора» (|S−H| = dMin); тело — та же точка минус смещение плеча.
- **Поворот на месте** крутит тело вокруг центра B, плечо обходит B по кругу, линия хода перестраивается через новое S. Если поворот увёл бы плечо от кисти дальше досягаемости или ближе dMin — **рука ведёт тело**: тело сдвигается вдоль руки на излишек (подтягивается / отталкивается), поворот идёт дальше (2026-11-20). Поворот останавливается, только если: телу некуда сдвинуться (стена, уступ); плечо вошло бы в стену или уступ; рука вошла бы в тело глубже, чем была (через грудь — предел ≈ −41°). Длина хода C = L − dMin, не больше.
- Кисть у кромки ближе dMin: ближний конец хода — там, где плечо сейчас (без рывка тела назад при хвате).
- **Клик** — луч курсора на поверхность. Точка прижимается к досягаемости и к сектору перед лицом.

## Поверхность по Y (зафиксировано 2026-11-18)

Статус: **зафиксировано автором, трасса с рельефом пройдена.**

**Точка на поверхности — и весь алгоритм прежний.** Функциональных кусков нет, поэтому выступ, пол, ступень, склон, углубление — это всё та же точка на плоскости, просто со своей высотой.

- Линия хода, жесты, поворот, сектор, стены — по-прежнему в XZ.
- **Курсор** — луч на поверхность (рельеф, а мимо него — пол). Алгоритм берёт XZ точки попадания.
- **Высота от своего уровня** `LevelHeight(p, уровень, подъём)`: луч вниз с «уровень + подъём». Всё, что выше (мост, перекрытие тоннеля), не мешает и не поднимает. Если ближайшая грань сверху смотрит вверх — точка внутри сплошного (бок галереи, ящик): это **выше порога**, стена. Пороги — в разделе «Пороги и преграды».
- `Height(x, z)` (самая верхняя поверхность) — только для старта и подсказок над стенами.
- **Тело** стоит на поверхности своего уровня под центром и плавно догоняет её на ступенях (`heightFollow`). **Плечо** — с телом. **Кисть** — на поверхности своего уровня; над уступом за порогом держит прежнюю высоту. **Локоть** опирается только на поверхность своего уровня (до порога), над высоким уступом висит между плечом и кистью.
- Подсказки (линия хода, сектор) лежат по рельефу своего уровня, над стенами — по верху.
- Физики и коллайдеров нет: треугольники рельефа (с нормалями граней) собираются один раз из корня `surfaceRoot`.
- Пол — бесконечная плоскость y = 0: ниже нуля ям нет. Поэтому на арене 2 основа поднята на 0.6, а тоннель — на нуле.
- Перепад плечо—кисть по высоте меняет длину руки **для зацепов и кромок** (досягаемость по 3D: чем выше точка над плечом, тем ближе по полу). Для обычного пола и ступеней — как раньше, L.

Рельеф трассы — отдельный корень «Рельеф (Y)», не под `obstaclesRoot` (иначе ступень = стена). Меню **Fortress → Hero → Proto: рельеф Y (пересобрать)**. По маршруту: склон 30 см и лестница вниз на старте; «горб» на 25 см с балкой 35 см; бордюр, камни, бугор в длинном коридоре; узкая лестница до 40 см; «змейка» поверху и длинный склон вниз; терраса 15 см в зале (ступень или пандус), уступ 35 см, ящик 60 см; спуск к финишу.

## Пороги и преграды (зафиксировано 2026-11-18)

Статус: **зафиксировано автором, арена 2 пройдена.**

**Пороги — от своего уровня:**

| | Тело | Кисть |
|---|---|---|
| вверх | `maxStep` = 0.4 м | `handUp` = 0.5 м |
| вниз | `maxDrop` = 0.4 м | `handDown` = 0.5 м |

- За порогом — уступ (вверх) или край (вниз). Для тела это **стена**: оно не встаёт туда, скользит вдоль, автообход отталкивает. Проверяется центр тела и четыре точки по краю круга.
- Ступени 12 см вверх и вниз, склоны — проходятся.
- **Тело встаёт на ступеньку сразу** (2026-11-22, автор: «залез полтелом внутрь ступеньки, а должен был сразу оказаться сверху»): высота тела — самая высокая **ровная** площадка под кубиком (центр, углы, середины сторон; ровнее `flatStepAngle` 10°), не выше порога шага. Склоны — по центру, как раньше; вскарабкивание не трогается. Бок галереи 1.2 м, ящик 60 см — стена. Край галереи и моста (вниз 1.2), ямы у тоннеля (вниз 0.6) — край, не упасть.

**Ввод работает всегда, отсекается исполнение** (принцип автора):
- Кисть ищется шагами 2 см по линии плечо → курсор и встаёт **перед первой преградой**: стеной (зазор 3 см), уступом/краем за порогом кисти или своим телом. Хват есть всегда, даже вплотную.
- Запрещённое (залезть выше порога, упасть ниже, войти в стену) не исполняется. Разрешённое (отъехать, развернуться) проходит.
- Рука **не проходит сквозь тонкую стену** (раньше `PushOut` выталкивал кисть на дальнюю сторону стенки).

**Плечо и рука не входят куда нельзя:**
- **Плечо** — круг 5 см: не входит в стены и уступы за порогом. Тело туда не едет, поворот на месте стоп.
- **Рука не сквозь тело**: отрезок плечо → кисть не ближе `armKeepOut` 0.15 м к центру тела. Если рука резала бы тело, направление кисти доворачивается к лицу до границы, **длина та же** (без скачка кисти к груди). Через грудь влево это ≈ 41° на любой длине руки. Поворот на месте стоп, когда рука входила бы в тело глубже; наружу — всегда можно.
- **Кисть не в теле** (2026-11-22, автор: «руку к углу поставил — не смог рассчитать», ход заперт вперёд и назад): кисть не встаёт внутрь кубика тела **и в щель между боком тела и плечом** (плечо 0.2 снаружи кубика 0.3) — **поворачивается вокруг плеча к лицу до края тела, длина руки та же** (непрерывно; первая версия выталкивала к ближайшей стороне — над телом сторона менялась, кисть перескакивала: «первые расстояния он тп»). Спереди зазор `handBodyGap` 3 см. Оттуда рука смотрела в центр тела: ближе — согнута до упора, дальше — сквозь своё тело, линия хода 2–14 см. Теперь у плеча линия 0.44–0.57 м.
- **Ввод из-за спины — зеркально** (2026-11-22, автор: «тяну за персонажем — хочу движение назад; рука как раз ставится ближе к телу, затем жест снизу вверх — персонаж двигается вниз»): курсор позади центра тела (по лицу) — **точечное зеркало через центр тела**: кисть встаёт **перед собой у тела, с другой стороны** (`behindHandDist` 0.22 от плеча): курсор сзади-справа → кисть спереди-слева, и тело, отъезжая от кисти, уходит назад-вправо — туда, где курсор. (Отражение только вперёд-назад оставляло кисть на той же стороне — тело уезжало в сторону, противоположную курсору: автор — «мышь вверх-влево, а уходит вниз-вправо».) Жест прежний: мышь снизу вверх («от себя») — тело уезжает назад на весь ход руки. `mirrorBehind`. **Руль при таком хвате прямой всегда**, при любом жесте: мышь вверх-влево — тело едет назад и уходит **вниз-влево по экрану** (лицо доворачивает вправо) — так решил автор по экрану. Раньше на диагонали задний ход включался через раз. Отвергнуто: кисть зеркально далеко + перевёрнутый жест; кисть за спину. Только хват за пол.
- **Поворот не отталкивает кисть у плеча** (2026-11-22, автор: «первые расстояния он тп»): кисть ближе `dMin` — поворот на месте держал руку не короче `dMin` и отталкивал тело до 12 см за шаг. Теперь нижний предел — как было до поворота.
- **Рука выводит тело** (2026-11-22): рука через грудь и «от себя» в дальний конец, обрезанный своим телом, — тело доворачивается в сторону, где руке свободнее (`backOutDegPerPx` 0.3°/пикс.), линия удлиняется, ход назад продолжается.

**Автообход (анти-вектор):** в ходе тела препятствия рядом отталкивают его — стены, стойки, уступы и края за порогом, стены у плеча. Сила 0 на `avoidMargin` 0.12 м от края → 1 при касании, `avoidGain` 1. Ход = желаемый + отталкивание × длину хода (скорость та же), потом скольжение и перестройка линии. В углу (стойка перил + основание лестницы) отталкивания складываются наружу — тело огибает с зазором, а не заклинивает.

## Подвижные элементы (зафиксировано 2026-11-19)

Отдельный блок `ProtoMover`: едет туда-обратно на `offset` со стоянками `wait` и/или крутится (`spinSpeed` непрерывно, `spinStep` рывками). Каждый шаг отдаёт свой сдвиг `Delta` (мир до → мир после) и номер шага; обновляется раньше героя.
- **Тело на платформе едет с ней** (место, высота, поворот лица). **Кисть, держащаяся за платформу, — тоже.**
- Тело и кисть на разных опорах: линия хода перестраивается через новое плечо; рука не достаёт — хват срывается.
- Платформы на 1 см выше пола: вровень — герой стоит на полу под ней, а не на ней.
- Лифт ставить вплотную к ярусу: щель даже 10 см — край за порогом спуска, не сойти.
- Мост, крутящийся непрерывно, не успеть поймать — крутится рывками по 90° со стоянкой.

## Вскарабкивание (зафиксировано 2026-11-19)

Статус: **зафиксировано автором, стенды арены 5 пройдены.** Отдельный блок `HeroProto.Climb.cs` (частичный класс поверх общего состояния).

**Цель ощущения:** каждый сантиметр выше порога куплен рукой. Держишься — на склоне хозяин; отпустил — склон забирает своё, но не сразу и у тебя на глазах.

| Правило | Как |
|---|---|
| **Крутой склон** | Круче 35° (выход при 32°) без опоры — тело сползает. Окно 0.2 с (`slideDelay`), дальше разгон `slideAccel`·sin(угла) до `slideMax` 1.5 м/с. Знак — сразу, в первый кадр. |
| **Кисть на крутом** | Без зацепа не держит: видимо съезжает (до 6 см) и отпускает. |
| **Зацепы** | Перила, поручни, столбы, ручки каруселей. Держат на любом склоне. Досягаемость — по 3D. |
| **Автозахват** | Курсор рядом с **любой** частью поручня (даже недосягаемой) — кисть берёт ближайшую точку, до которой достаёт. Радиус: `holdSnapScreen` 0.15 высоты экрана на склоне / над пустотой, `holdSnapScreenFloor` 0.06 над нормальным полом (чтобы пол рядом с перилами оставался полом). |
| **Кромка уступа** | Выше порога шага, до `climbUp` 0.8: кисть ложится на верх, если под ним сплошное (крышу тоннеля снизу не взять) и он в досягаемости по 3D. Кисть сначала ищет пол в обычных пределах руки, и только если там стена — кромку выше. |
| **Подтягивание** | У кромки жест «на себя» поднимает тело (`climbPerPx` 0.0012 м на пиксель: уступ 0.5 — ~300 px, 0.7 — ~500 px). «От себя» — опускает. |
| **Перевал** | Поднялся настолько, что уступ стал ступенькой, — тело само заходит наверх, пока держишься (`mantleSpeed`). Отпустил до перевала — опускается туда, откуда поднимался (не падение). |
| **Рука держит вес** | Досягаемость меняется с высотой тела; рука подтягивает тело к кисти; упёрлось и не достаёт — хват срывается. |

**Видимый отклик (только знаки в мире):** тело тёплое — сползает; фиолетовое — висит на кромке; зелёная вспышка — перевал; кисть жёлтая — на зацепе или над ним; красная — съезжает, не держит; линия руки красная — рука держит вес.

**Замеры (бот):** висение 10 с на 60° за поручень — 0 см; знак сползания — 20 мс; потеря 0.3 м — 0.62 с на 60°, 0.70 с на 45°; подъём на уступ 0.5 — 4 жеста, 0.7 — 10, 1.0 — нельзя; 45° с перилами справа — 18 жестов, 60° справа — 24, 60° слева — 44–115 (через грудь, только боком); без перил 45° и 60° — нельзя.

## Хват за выступы (зафиксировано 2026-11-20)

Статус: **зафиксировано автором, стенды арены 7 пройдены.** Отдельный блок `HeroProto.Ledge.cs` (частичный класс поверх общего состояния), маркер `ProtoNub.cs`. В прежних версиях — «автозацеп r» (r = 0.15 м, выступ важнее пола).

## Предметы: физика Unity (переделка 2026-11-22, на проверке у автора)

Статус: **переделано, не проверено автором.** Блоки `HeroProto.Drag.cs` (наведение, хват, перенос), `HeroProto.ItemPhysics.cs` (мир для предметов, толчок телом), `HeroProto.Back.cs` (слот на спине, выключен), предмет `ProtoItem.cs`. Зона 10 арены (старт).

**Почему переделка** (автор: «ты усложняешь схему — стоит её перевернуть, удалить лишнее и получить работающий механизм физичных объектов»; «запульнул объект в воздух»). Предметы жили в двух мирах: свои правила по габаритам (опоры, стопки, «влезает ли», оседание, подъём, выпрямление, равновесие) и физика Unity поверх (падение, кинематический перенос, «разбудить верхних», толкатель тела) — правила спорили, наклонные висели в воздухе, кинематический толкатель высотой метр бил углами при повороте. Теперь **предметы целиком на физике Unity, «позиции» — только у тела героя.**

| Правило | Как |
|---|---|
| Предмет | Всегда физическое тело Unity: `Rigidbody` + `BoxCollider`, **масса** (`mass`, кг), трение, сон в покое. Стопки, падение, наклон, «вытащить снизу», «поставить на наклонный» — сама физика. |
| Мир для предметов | Неподвижные коллайдеры (`EnsureItemWorld`, один раз): рельеф и стены по сеткам, пол y = 0. Тела героя в физике **нет**. |
| Ловля | Только курсор на самом предмете (луч в его коллайдер) и рука до него достаёт. Кисть рядом с предметом его не ловит (автор: «хотел двигаться, а зацепился»). Верх стопки — первым. |
| Хват | ЛКМ — кисть держит предмет за верх в точке, куда указала; **тело не едет**, жесты езды и поворота не работают. Состояние «тащит предмет». |
| Перенос | Цель кисти идёт за курсором по правилам свободной руки. Предмет ведёт к цели **сила руки**: желаемая скорость (`carryGain` × расстояние, не быстрее `carryMaxSpeed` 2.5 м/с), разгон не больше `carryForce` 60 Н / масса, поддержка против тяжести из той же силы — **тяжёлый тащится медленно и не поднимается**. Высота цели — по опоре под следом (луч физики: пол, ступень, другой предмет, не выше досягаемости) — сам заезжает на ступень и на другой предмет; в стены и ступени упирается сам; стопку на нём везёт трение, рывок роняет. Цель не входит в тело (`itemBodyGap`). Точка хвата ушла дальше руки на `carryBreak` — не удержал. |
| Отпустил | Дальше просто физика: встанет, съедет, упадёт, сядет под углом. Падение героя — предмет выпал. |
| Тело и предметы | **Лёгкий** (не тяжелее `pushMaxMass` 5 кг): тело входит в его след — мягкий толчок по горизонтали от центра тела (`pushSpeed` 0.6 м/с), вверх — никогда. **Тяжёлый** — стена для тела (Blocked, скольжение, автообход). Автообход от всех предметов остаётся. |
| На спину (LOCK) | **Выключено** (`backSlot`, автор: «мешает»). Включённое: тащишь, курсор за спиной — отпустил, предмет на теле (физика выключена, место от тела); снять — ЛКМ по нему. |
| Зона 10 | Ящик 3 кг, свёрток 0.5, бочонок 12 (тяжёлый), доска 2, камень 1.5 — после пересборки арены. |
| Удалено при переделке | Габариты для опор и стопок, «влезает ли» предмет, оседание, плавный подъём, выпрямление, «разбудить верхних», кинематический перенос, проверка равновесия, толкатель тела. |

## Как делаем механику (цикл)

0. Нарезать на шаги «одно правило — один шаг».
1. Правило + инварианты + **цель ощущения** (геймдизайнер, один раз на механику).
2. **Таблица стыков:** новое правило × каждая старая система (пороги, стены, автообход, рука↔тело, поворот, хват, платформы, ввод) × типовая геометрия (стена, угол, край, тонкая стена, щель, лестница, подвижная опора, ровно порог).
3. Стенды — подписанные, чтобы автор мог пройти.
4. Реализация отдельным блоком.
5. Прогон: сценарии + **сторожа** на каждом кадре + **бот-бродяга** по всем аренам + замеры ощущения.
6. Регрессия на старых аренах.
7. Отчёт: что прошло, что починено, что может проверить только автор.
8. Автор проходит: делал ли то, что хотел? где непонятно, почему нельзя? тяжело как задумано или неудобно?
9. «Зафиксировали» → md + коммит + тег.

Симуляция для этого — `Editor/HeroSim.cs`: в Play шаги вручную (платформы → герой → камера → сторожа), без живых кадров. `Fuzz(секунды, seed)`, `Stand(...)`, `Arena5()`, `Feel5()`.

## Жесты при зажатой ЛКМ

Жест раскладывается **локально**: экран = камера за спиной = тело. Где кисть, неважно.

| Мышь | Действие |
|---|---|
| **вниз** (на себя) | тело едет по линии к кисти |
| **вверх** (от себя) | тело едет по линии от кисти |
| **вправо / влево** | **поворот на месте** («лопасти вертолёта»): тело крутится вокруг центра, кисть стоит на полу. **Вправо = поворот вправо.** |
| отпустить ЛКМ | тело остаётся, рука снова свободна |

- Обе части жеста работают **одновременно и без рывка**: можно крутиться и толкать себя одним движением. Поэтому за одно зажатие можно уехать дальше C.
- Пиксели по вертикали переводятся в ход 1:1 к длине линии хода на экране.
- **Перёд и зад различаются:** лицом вперёд — сила 1.0 (`forwardSpeed`), спиной — 0.45 (`backSpeed`). Между ними плавно, по углу хода к лицу.
- **Зона поворота** — 180° за один хват, по 90° в каждую сторону от лица (`turnZone`). Чувствительность поворота 0.4 (`turnSensitivity`), поворот доворачивается плавно (`turnSmooth = 10`).

> ⚠ **Знак поворота НЕ МЕНЯТЬ:** `deg = −sidePx`, `sidePx = md.x`. Если поворот «кажется обратным», проверь, стоит ли камера за спиной тела. Однажды тело стартовало повёрнутым на −90°, а камера на 0°, и из-за этого знак дважды меняли зря.

## Два слоя вокруг лица («лицо там, где рука»)

1. **Движение (разброс руки):** сектор −50°…+70° от лица; рука правая, поэтому вправо шире. Сюда ставится кисть. Внутри сектора езда работает в полную силу.
2. **Поворот:** шире движения. Между краем разброса и 100° (`moveFadeLeft/Right`) езда плавно гаснет; поворот ограничен зоной поворота.

## Камера (отдельный блок `ProtoOrbitCamera`)

- **Вправо-влево** камера крутится **только вместе с телом**: поворот жестом ЛКМ поворачивает и вид (`followBodyTurn`).
- **ПКМ (зажать) + мышь вверх/вниз** — наклон камеры 10°…85°. Пока ПКМ зажата, рука замирает.
- **Колесо** — ближе / дальше (0.8…8 м).
- На старте камера встаёт за спину телу (`startBehindBody`).

## Препятствия (без физики)

- Тело — круг r = 0.2 м. Препятствия — прямоугольники по габаритам кубиков под `obstaclesRoot`.
- **Материал стены:** тело не входит в препятствие, а **скользит вдоль него** — составляющая «в стену» убирается. Трение `wallFriction = 0.15` (0 — лёд, 1 — липкая стена). В углу стены обрабатываются по очереди, до трёх. После скольжения линия хода перестраивается через кисть и новое место плеча.
- **Тело никогда не ставится в стену:** любой ход (езда, начало хвата) идёт от фактического места тела через проверку и скольжение. Если тело всё же внутри — выталкивание наружу по нормали.
- Кисть не встаёт внутрь препятствия и не проходит сквозь него: встаёт перед ним (раздел «Пороги и преграды»).
- Проходы делать **не уже 0.8 м**: тело 0.4 + плечо сбоку + зазор автообхода. Щель 0.4 м — ровно тело, не пройти.

## Трасса

Текстовая карта, клетка 0.6 м: `#` стена, `o` столб, `S` старт, `F` финиш. Генератор и проверка поиском пути — в scratchpad сессии (`course/gen.py`, `bfs.py`); сама карта встроена в сборщик.

Маршрут: старт → коридор 1.2 м → «горб» → узкий подъём 0.6 м → «змейка» из трёх шпилек 0.6 м → зал со столбами в шахматном порядке → узкий проход → финиш. Кратчайший путь 58 м, 22 поворота.

## Чему научились (не повторять)

- Симуляция «всего сразу» (IK + физика + автонаведение + перехват в одном контроллере) ломала одно, когда чинила другое. Позиции и блоки — работают.
- Жест раскладывается локально (X — поворот, Y — езда). Раскладка относительно линии хода на экране поворачивается вместе с линией, и при кисти сбоку управление «едет».
- Пересобирать сцену можно только вне Play: в Play сохранение молча не проходит, а пересборка рушит объекты в запущенной игре.
- Пока автор тестирует, Unity не трогать: правки только в коде, компиляция вне Unity.
- Плечо сбоку (2026-11-18): без ограничения поворота и без проверки стен на каждом шаге тело «прыгало» к кисти и застревало в стене — скольжение из точки внутри стены не двигает. Ставить тело только через проверку; застрявшее — выталкивать.
- Значения, выставленные в Play, при выходе откатываются: в сцену писать после Play. Gizmos окна Game тоже сбрасываются.
- Высота по **самому верху** ломает ярусы: под мостом и в тоннеле тело выносило наверх. Считать от своего уровня.
- Один порог «выше — стоп» без высоты от уровня сделал бы стеной мост над головой.
- Суставы брали высоту по верху и прыгали на ступени — суставам тоже только свой уровень.
- Отказ от ввода вплотную к уступу (кисть не ставится) запирал героя: нельзя даже отъехать. Ввод — всегда, отсекать исполнение.
- `PushOut` кисти к ближайшему краю выталкивал её на дальнюю сторону тонкой стенки. Искать кисть шагами от плеча.
- Укорачивать руку вдоль луча (при упоре в тело) — кисть скачком прыгала к груди. Доворачивать угол, длину не трогать.
- Скольжение вдоль стен не спасает в углу двух стен — нужен анти-вектор (автообход).
- Залипание «на глаз» не воспроизвести: автор оставляет Play включённым, состояние читается вживую — так причина находится сразу.
- Сдвиг зоны ввода вниз (курсор + четверть экрана) автор отверг; курсор ниже персонажа (луч в пол за спиной) — открытый вопрос.
- Модель вместо кубиков: с камерой за спиной видна только спина, лица нет — пока кубики.
- Бот со сторожами ловит баги на стыках, которые автор находил «ползая»: рука резала тело при скольжении, тело дёргалось на линию хода, ловушка в тоннеле (новая досягаемость вверх спрятала пол под перекрытием), рывок на перевале. Прогонять на **всех** аренах, не только на новой.
- Увеличивая радиус ввода, сохранять «ближайшая допустимая точка»: радиус в пикселях без подстраховки «ближайшая достижимая точка того же поручня» оказался хуже — снова приходилось целиться.
- Большой радиус автозахвата везде крадёт хваты за пол рядом с перилами — над хорошим полом радиус меньше.
- Перекрытие над своим полом (тоннель, мост) ловило указатель: курсор упирался в крышу. Луч проходит сквозь крышу, если под ней есть пол своего уровня.
- Высокие стены арены за спиной героя закрывали камеру на старте — стены испытательных арен держать низкими.
- Модель героя должна подниматься вместе с подъёмом на кромке (`BodyGround` с подъёмом), иначе тело остаётся на полу.
- «Поворот работает только в одной зоне экрана» (2026-11-20) — не про курсор: в хвате курсор не читается, только сдвиг мыши. Дуга вверх = «от себя», рука вытягивалась до упора, а поворот, удлиняющий руку, был запрещён. Не запрещать — пусть рука ведёт тело.
- Выступ по геометрии («мелкий кубик») поймал бы ступени и бордюры — только маркер от сборщика.
- Замер на подвижном элементе зависит от фазы: перед ним ждать, пока элемент подъедет.
- Кисть на челноке, тело стоит — рука растягивается и срывается: «не физично». Тело едет за опорой кисти; тягу ограничить за кадр, иначе на лифте рывок.
- Вспышка перевала на склоне (кисть на склоне сочтена кромкой) давала залезть по диагоналям без зацепов — кромка только выше порога шага над уровнем.
- Камни-ступеньки в колонке через 17 см при радиусе 16 см — сплошная лестница, съехать нельзя. Без руки на новый камень не ставить, сползающее тело камни не ловят.
- Лестница вниз: тело не шло ни ездой (dMin), ни через проверку края (подъём камня считался обрывом), ни через `Slide` (проверка руки). Свой шаг с проверкой только стен, плеча и глубины.
- «Назад» на крутом требовало дальнего конца линии — на 60° тело упирается раньше. Отпускать и когда тело не сдвинулось.
- Стойки у карусели близко к диску — тело заносит в них. Ставить с запасом.

- (2026-11-21) Бот в ручных шагах не видит живой цикл: FixedUpdate 50/с сломал ощущение (ступеньки на 247 кадрах), а замеры совпали. Живой сторож (`ProtoLiveWatch`) нужен рядом с ботом.
- Сетка с эталоном (каждое изменённое число) + сброс мира перед замером — прогон повторяем до цифры; зацепы и платформы упорядочивать по имени, иначе пересборка сцены меняет числа.
- Твёрдые камни (стоять, лестница) дали много багов — вырезаны. Вернуть их «сбоку» ради «не налезать на камни» — то же самое, автор против. Чинить правила движения, а не твёрдость.
- Подъём «вис над склоном»: отпустил камень — тело падает рывком «на нижний камень». На склоне тянуть ВДОЛЬ склона.
- Рисовать локоть по полу, а высоту отдельно — звенья тянутся. Только 3D с длинами звеньев.
