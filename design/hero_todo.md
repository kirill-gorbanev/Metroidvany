# Долг контроллера героя — список шагов

> ⚠ **Список долга старого контроллера `HeroProto` (история, 2026-11-25).** Новый контроллер — на физике Unity: см. `design/prompt_fable_hero_controller.md` и `design/hero_arm_knowledge.md`; при противоречии прав новый. Здесь устарело: «FixedUpdate 50/с отвергнут» (теперь `FixedUpdate` с интерполяцией и мелким шагом), «полёт без физики» в падении (падение на физике, `b37ac8c`), «решено без Unity-физики» в столкновениях (теперь физика). «Лицом вперёд край — стена» совпадает с новым: передом не сваливаться.

Правило: **один шаг — сделал Claude → проверил автор.** Следующий шаг только после «ок» автора.
Отметки: `[ ]` не начато · `[~]` сделано, ждёт проверки автора · `[x]` автор проверил.
Точка отката перед долгом: тег `proto-ledge-course` (2026-11-21).

## Сетка (перед каждым коммитом)

`tools/herosim/run_all.sh` — все арены 2–8: бродяга на 3 зёрнах + замеры каждой арены + подъём по камням (`Climb7`), мир сбрасывается перед каждым замером (`HeroSim.ResetWorld`) — прогон повторяется до цифры. Сравнение с `tools/herosim/baseline.txt`: печатается **каждая изменённая строка**. Живая проверка (`~`, настоящий цикл игры) на аренах 7 и 8 — рывки и платформы без шага. `./run_all.sh accept` — новый эталон (после «ок» автора). `ARENAS="7 8" ./run_all.sh` — только эти арены.

## Шаги

1. `[x]` **Пороги жестов в долях экрана.** Все жесты в одних единицах — доля высоты экрана (эталон 1080 px: на 1080 ничего не меняется). Подъём у кромки, «отпустить», лестница вниз раньше были в сырых пикселях, а езда и поворот — уже в долях. Бот и замеры — тоже в долях.
   *Автор проверяет:* ощущение как раньше; окно Game маленькое и на весь экран — одинаково.
2. `[x]` **Шаг не длиннее 0.02 с.** Каждый кадр делится на шаги ≤ 0.02 с (как у бота); платформы шагает герой, раньше себя; подвис дольше 0.25 с — замедление, не прыжок. Мышь копится. (Проба FixedUpdate 50/с отвергнута: на мониторе 247 кадров/с карусель и тело шли ступеньками, хват стал труднее — автор 2026-11-21.)
   *Автор проверяет:* плавность; переключить окно во время езды — без рывков.
3. `[x]` **«Отпустить» не работает** (жест «от себя» на крутом). Ловить на руках автора в Play.
4. `[x]` **Одна арена «всё сразу» — сделано.** `Scenes/HeroArena.unity`, меню **Fortress → Hero → Build Arena (всё сразу)**: прежние арены 2–8 — зоны на своих прежних координатах, активна одна (клавиши 2–8, `ProtoZones`); старые сцены и пункты меню вырезаны (остались в git). Замеры перенесены без правок (координаты те же); зацепы и платформы упорядочены по имени — прогон не зависит от пересборки сцены.
5. `[x]` **Столкновения — часть 1 сделана: подвижная стена толкает тело** (`HeroProto.Push.cs`): тело сдвигается вместе со стеной, вдоль неподвижных скользит; зажало — «раздавлен» (пока — на последнее безопасное место, сторож пишет). Замер `Push8`: раньше стена проходила сквозь тело (сторож «тело внутри уступа» ×20), теперь тело едет перед ней 3 м, самый большой сдвиг за шаг 3.5 см. **Часть 2 сделана: тело сталкивается своим кубиком** (`HeroProto.Body.cs`: повёрнутый прямоугольник по размеру кубика 0.3 × 0.3; стены — разделяющие оси; уступы и обрывы — пробы по углам и серединам сторон, раньше было 4 точки по осям и угол заходил в уступ по диагонали; поворот на месте, при котором угол вошёл бы в стену, не делается). Стенды те же, полоса арены 6: этап 10 (пропасть, челнок) теперь проходится. **Часть 3 сделана: рука не сквозь склон** — локоть поднимается так, чтобы оба звена шли над поверхностью с зазором 3 см (только рисунок). Замер `tools/herosim/arm_clearance.cs`: 60°, кисть на камне выше — было −9.5 см (сквозь склон), стало +2.9 см. Остаток: первые 0.2 с после хвата кисть догоняет высоту плавно и может мелькнуть ниже склона. (Решено без Unity-физики: стены здесь — и кубики-препятствия, и любой край выше шага, их знает только своя геометрия.)
6. `[x]` **Селектор состояний по приоритету — этап 1 сделан** (`HeroProto.State.cs`): одно состояние на шаг, первое сверху (хват: вис → лестница вниз → кисть съезжает → на зацепе → хват за пол; свободна: слёт → сползает → окно склона → стоит на камне → на диске → стоит), наложения (едешь с опорой, опора кисти тянет, «отпустить» N%, жест → кому), строка «Состояние: …» в подсказках, переходы «А → Б» считает бот (строка «переходы» в прогоне), выносливость `gripStamina` = ∞. Поведение не изменилось — все числа прогона совпали. **Этап 2** начат: все выходы из хвата (было 9 мест с разными сбросами) — через один `ReleaseGrip(причина)`, причина видна в журнале переходов; прогон — ни одно число не изменилось. Дальше (по одному с эталоном): переносить логику каждого состояния в его ветку (вход / шаг / выход) вместо флагов в Tick.
7. `[x]` **Падение — сделано** (`HeroProto.Fall.cs`, правила — геймдизайнер). Начинается: **спиной с края** (ход назад упёрся в обрыв глубже 0.4, дожим «от себя» 60 px — тот же закон, что «отпустить»), **сполз** со склона к краю, **опора ушла** (платформа увела, рука не держит), **отпустил вис** выше 0.4. **Лицом вперёд край остаётся стеной.** Полёт без физики: отступ от кромки 0.3 м за 0.12 с, переносимая скорость опоры (≤ 3 м/с), y = y0 − ½·20·t² (≤ 12 м/с); в первый 1 м полёта клик по зацепу / камню — вис. Цена по высоте × масса (1): ≤ 0.4 ничего, ≤ 1.5 присел 0.25 с, ≤ 3 оглушение 1 с, ≤ 4.5 тяжёлое 2.5 с, выше — смерть (пока — на старт зоны). Состояния «падает» / «оглушён» в строке состояния. **Зона 9 «падение»** (клавиша 9): площадки 1.2 / 1.8 / 3.2 / 4.6 с лифтами, склон 45° в обрыв 1.7. Замер `Fall9`: 1.2 — присел, 1.8 — оглушение, 3.2 — тяжёлое, 4.6 — смерть, лицом к краю — 0 падений, «передумал» — дожим заново, склон — сполз и оглушение. **Открыто для автора:** лицом вперёд край — стена (так решено по умолчанию)? смерть уже сейчас? общая шкала «масса × величина» для падения и зажима?
8. `[~]` **Тело лёжа на животе — проба, по умолчанию НЕ включено.** Замер модели ничком (`tools/herosim/measure_prone.cs`, `HeroBody.prone = 1`): длина 0.93 (таз → макушка, ног у модели нет), корпус ≈ 0.44 (с правой рукой 1.18), спина ≈ 0.28, правое плечо 0.20 вправо и 0.27 вперёд от центра на высоте 0.26, рука 0.49. Сделано: плечо может быть впереди центра (`shoulderForward`), тело сталкивается своим длинным кубиком (шаг 5.2), меню **Fortress → Hero → Build Arena (всё сразу, тело лёжа — проба)** собирает арену с телом 0.44 × 0.28 × 0.9, рукой 0.25 + 0.24, сгибом 0.14. **Результат пробы** (`tools/herosim/prone_report.txt`): стенды арены 5 «как задумано» 6/11 (стоя 10/11) — уступы 0.5 / 0.7 и склоны с перилами не берутся, висение на 60° срывается, перевал не наступает. **Причина — модель, а не числа:** длинное тело на 60° концами расходится по высоте на 0.78 м, а пробы уступов меряются от уровня центра — тело «упирается» на любом крутом склоне. **Нужно (решение автора):** тело наклоняется вдоль склона (пробы — от плоскости тела), пороги кромки и подъёма — под руку 0.49 и плечо на 0.26, арены — под длинное тело (повороты в проходах 0.8 м длинному телу не даются: диагональ ≈ 1.0 м).
9. `[ ]` **Умная камера — ВЫКЛЮЧЕНА автором** («отключи этот эффект камеры»; камеру делать по описанию автора). Код остался (`smartCamera` = false). Было сделано (`ProtoOrbitCamera`, `smart`): **лазание** (висишь, стоишь на камне-ступеньке, на крутом, держишься выше плеча) — наклон меньше на 22° (смотрит вверх), взгляд к кисти; **взгляд впереди тела** на 0.45 м — герой ниже на экране, впереди больше места (курсор реже уходит ниже героя); **стена / уступ / крыша между героем и камерой** — камера подъезжает (не ближе 0.7 м). Замер `tools/herosim/cam7.cs`: ровный пол — 0 / 50° / 2.6 м; хват на 60° — лазание 1 / 28°; тоннель зоны 6 — 0.7 м. Стенды и провалы — те же, что без камеры. Попутно: свободная кисть, догоняя курсор, больше не проходит сквозь тело (огибает его вокруг плеча).

## Отложено / заметки

- **Итог 2026-11-21 (проверено автором):** рука в 3D (длины звеньев сохраняются, кулак не в поверхность, лимит учитывает поверхность); синяя зона руки — жёсткий фильтр для любого движения тела при хвате; задний ход как в автомате (`reverseSteer`); курсор не уходит за окно, пока держишь ЛКМ; первые 0.4 с после хвата «отпустить» не копится; камни только для руки, тело тянется к камню вверх по склону и останавливается у него; склоны с камнями — подъём 45°, спуск 60°; шаг камней везде 0.25; подъём на камне 0.0012 м/px; умная камера выключена (`smartCamera`).

- Камни НЕ твёрдые ни сверху, ни сбоку (автор 2026-11-21: «МЫ УДАЛИЛИ твёрдые камни»). Единственное: подтягивание к камню останавливается, когда тело коснулось камня, за который держишься (не налезть на него).

- **Склоны с камнями — 45°, не 60°** (автор 2026-11-21: «дальше 60 градусов макс сложно, и тут тоже баг — угол ставить меньше»): арена 8 этап 1 и зона 7 дорожка 1 — 45° (спуск, этап 2, остаётся 60° — автор: «этот угол тоже норм»), шаг камней 0.25; дорожка 8 (60° камни только для руки) убрана — после вырезки твёрдых камней она повторяла дорожку 1. Дорожка 2 «60° без камней — нельзя» оставлена. Нужна пересборка арены.

- **Твёрдые камни вырезаны (автор 2026-11-21: «много багов — отказываемся»).** Все камни — только для руки (как этап 3 «45° камни только рука», который работает идеально): стоять на камне, «камень под ногами», лестница вниз и вверх по камням, их замеры (G, H3), состояния «стоит на камне» / «лестница вниз» — убраны. Спуск по камням — съезжай и лови камни рукой. Подписи стендов обновятся после пересборки арены (меню Fortress → Hero → Build Arena (всё сразу), вне Play).

- Рука (2026-11-21, `06b59ff`): локоть — два звена в 3D, длины звеньев сохраняются, локоть не уходит в поверхность (плоскость сгиба поворачивается вверх). Заменяет подъём локтя из шага 5.3, который растягивал звенья. **Автор проверил: «идеально».**

- Замер Spin4 №5 (зона 4, 120°/с за столб, «на себя» 3 с) после пересборки арены даёт r 0.15 или 0.28 — единственное число, которое ещё зависит от пересборки сцены. Найти, что в нём зависит от порядка объектов.

- Лифт опускается на тело, стоящее под ним (полоса арены 6, этап 12): тело несколько шагов «внутри уступа», потом выталкивается, бывает «раздавлен». Зажим сверху — по шкале «масса × величина» (смерть), когда автор решит.
- Хват в полёте ловит и поручень, но вис после поимки держится только на камне / кромке; поручень — тело снова падает. Решить, держит ли поручень вес в полёте.
- Таблица переходов показала дыру: на арене 5 бродяга не выходит из «стоит ↔ хват за пол» — лазание там проверяют только стенды. Боту нужны цели на склонах и уступах (или стенды «туда-обратно»).

- Стенд 8 (камни только для руки), 2026-11-21: мёртвая зона «на себя» (камень выше тела < 0.4 и над плечом — ни езды, ни подъёма) — исправлено в шаге 3 (вис с 5 см, подъём на камне 0.0024 м/px). Та же мёртвая зона была на стенде 1 (камни-ступеньки) — исправлено «лестницей вверх» (зеркало лестницы вниз): каждый камень 230 px, стенд 1 — 17 жестов (было 23), стенд 3 — 12 (было 18). Ждёт проверки автора.

- Дёргание, когда кисть внутри тела / у стены челнока (скрин автора 2026-11-21, арена 7: кисть между телом и стеной у камня) — смотреть в шаге 5.
